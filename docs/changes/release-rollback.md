# Выкатка с откатом и /api/health — план и трассировка

**Статус:** реализовано в ветке `ops/release-health` 2026-09-27; на сервере не проверено (сервера нет).
Этапы 3 (частично), 4 и 7.1 [ops-плана](ops-readiness.md); пункты C1, C2, C4 [roadmap](roadmap.md).
**Источники:** ops-readiness.md § этапы 3, 4, 7; DEPLOY.md § 2, 3, 6; аудит C (project-audit.md).

Проверка: **T** — автотест (`deploy/release.test.sh`, в CI), **H** — HTTP к dev-серверу, **B** — `npm run build`,
**M** — вручную на сервере.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Раскладка | `releases/<дата>-<sha>`, симлинк `current`, `shared/.env`; база и картинки — `/var/lib/armreview` | новая сборка не трогает работающий релиз; откат — переключить симлинк |
| Откуда код | зеркало `repo.git` + `git archive <sha>` | в релизе нет `.git`, ровно тот коммит, что просили |
| Картинки | `staticDir` из `MEDIA_DIR` (дефолт `media` — локальная разработка) | Payload не резолвит путь, относительный — от cwd, т. е. от папки релиза |
| Порядок | бэкап → код → `npm ci` + `build` → `migrate:status` + `migrate` → `current` → restart → `/api/health` | бэкап до всего, что пишет в базу (в production и сборка — `prodMigrations`) |
| Переключение | `ln -sfn` во временное имя + `mv -Tf` | атомарный rename: `current` не бывает «пустым» |
| Проверка | `/api/health`: `payload.count('events')` → `200 {"ok":true}` / `503 {"ok":false}`, `no-store` | жив процесс, база и её схема; наружу ничего лишнего |
| Откат | не ответил за 30 с — `current` на прежний релиз, restart | код откатывается сам; **миграции — нет** (SQLite без транзакций) → восстановление из бэкапа по DEPLOY.md § 5 |
| `prodMigrations` | **оставлен** | убрать можно только после проверки чистого bootstrap на стенде (аудит C); после явного `migrate` он ничего не находит |
| Права | скрипт — `sudo`; сборка, git, миграции — от `armreview` (`runuser`) | `systemctl` нужен root, файлы релиза — пользователю приложения |
| Хранение | 3 последних релиза, текущий и прежний — никогда не удаляются | место на диске |

## Сценарии

| # | WHEN | THEN | Проверка |
|---|---|---|---|
| 1 | первый релиз, базы нет | бэкап пропущен; код из git, `.env` — симлинк на `shared`; ci → build → migrate:status → migrate → restart; `current` → новый | T |
| 2 | обычный релиз | бэкап до сборки; `current` → новый; прежний релиз на диске | T |
| 3 | сборка упала | `current` не тронут, папка релиза удалена, ни миграций, ни перезапуска | T |
| 4 | миграция упала | `current` не тронут, без перезапуска, подсказка восстановить базу из бэкапа | T |
| 5 | новый релиз не ответил на `/api/health` | `current` вернулся, перезапуск прежнего, код ≠ 0, сообщение об откате | T |
| 6 | бэкап упал | сборки нет, `current` не тронут | T |
| 7 | несуществующий ref | ошибка, `current` не тронут | T |
| 8 | 5 релизов подряд | остаётся 3, `current` — самый новый | T |
| 9 | `GET /api/health`, база доступна | `200 {"ok":true}`, `Cache-Control: no-store` | H |
| 10 | база недоступна | `503 {"ok":false}`, в ответе нет текста ошибки | H |
| 11 | `/api/health` не кешируется сборкой | маршрут динамический (`ƒ`) | B |
| 12 | `MEDIA_DIR` задан | загрузки и выдача картинок — из него | M (стенд) |
| 13 | настоящий сервер: `sudo release.sh main`, затем откат по § 6 | как в T, с systemd, npm, Caddy | M (стенд) |
