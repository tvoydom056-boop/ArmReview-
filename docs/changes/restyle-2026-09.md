**Статус:** план. Кода нет и не будет до «ок» Danil'а (CLAUDE.md «план → ок → код»).
**Что закрывает:** перенос макетов [`design/*.html`](../../design/index.html) в реальные страницы
приложения — токены, общие примитивы, 8 страниц из [`design/README.md`](../../design/README.md).
**Источники:** [`design/README.md`](../../design/README.md), [`design/ui.css`](../../design/ui.css),

**Отличие от прошлого рестайла:** [`restyle-dark-dashboard.md`](./restyle-dark-dashboard.md)
(коммит `2d1856d`, 19.09) уже завёл токены, обе темы и `ThemeToggle`. Макеты `design/` — это
следующая, более детальная итерация той же системы (макеты от 20.09): новые примитивы (пилюли-исходы,

Это не финальный дизайн — это план **какие файлы трогать и в каком порядке**, чтобы перенос был
проверяемым по шагам, а не одним огромным диффом.

## 1. Что переносим, а что нет

**Переносим (визуал + минимум новой разметки, роуты и данные не меняются):**
токены `globals.css`, общие примитивы `ui.module.css`, все 8 страниц из README, кроме блоков
ниже.

**Не переносим сейчас — упирается в схему БД (не код-ревью, а факт: полей нет):**
бейдж стиля (`stylebadge`, `.t-inside/outside/universal`), шкала инсайд↔аутсайд (`.scale`),
подсветка шапки по типу (`.hero--inside/outside/universal`, `.avatar--inside/…`), распределение
по стилям (`.stack` на странице борца), кольцо `ph--inside/…` на карточке в `/athletes`. Это
ровно то, что в макетах помечено `.future` («НЕТ ДАННЫХ В БАЗЕ») — ждёт
[`athlete-stats-data-model.md`](./athlete-stats-data-model.md) и ответов Влада на вопросы 18/21/22.
Токены `--inside/--outside/--universal(-tint)` заводим **вместе с тем планом**, не сейчас —
иначе это неиспользуемый код (AGENTS § 4.5).

**Не переносим вообще — в реальных страницах не используется:**
`.donut` (кольцевая диаграмма) и `.meter` (светофорная шкала) есть только в
`components.html`/`states.html` — витринах дизайн-системы, ни в одном роуте не встречаются.
`.future`-плашка — пометка для макета, в приложении её не будет никогда (README).

**Требуют отдельного решения перед переносом** — см. § 3.

## 2. Токены — `globals.css`

Сверка `design/ui.css` ↔ текущий `globals.css` (полный список токенов обоих файлов сверен построчно):

| Токен | Есть сейчас | В `design/ui.css` | Действие |
|---|---|---|---|
| `--bg --surface --border --border-strong --overlay --text --muted --win --loss --gold(-bg/-border) --radius-* --transition --font-display` | да | да, те же роли | не трогаем |
| `--surface-hover` | да (тёмная `#1c1d23`, светлая `#ececf0`) | но это значение — новый `--surface-2` | **переименовать значение**: текущее значение `--surface-hover` становится `--surface-2`; `--surface-hover` получает новое, более контрастное значение из `design/ui.css` (тёмная `#22232a`, светлая `#e3e3e9`) |
| `--surface-2` | нет | да | добавить (см. выше — это старое значение `--surface-hover`) |
| `--maxw` | нет (в `globals.css` захардкожено `960px` в `.site-main`) | `1100px` | добавить токен, `.site-main` переключить на `var(--maxw)` — расширение центральной колонки с 960 до 1100px |
| `--font-body` | нет (стек шрифта захардкожен в `body`) | да | добавить токен, `body { font-family: var(--font-body) }` — тот же стек, просто через токен |
| `--warn` | нет | да | **не добавляем** — используется только в `.future`-плашке и `.meter`, ни то ни другое в приложение не идёт |
| `--inside --outside --universal` (+`-tint`) | нет | да | **не добавляем сейчас** — см. § 1, заводим вместе с `athlete-stats-data-model.md` |

**Побочный эффект `--surface-2`/`--surface-hover`:** все текущие `:hover`-состояния
(`cardInteractive`, `.athletecard`, `.chip`) станут чуть контрастнее — это ожидаемо и совпадает
с макетом, не регрессия. Слегка отличается от текущего лишь количественно, не качественно.

**Дефолт темы не меняем.** В `design/ui.css` тёмная тема — это `:root` по умолчанию, светлая —
только через `[data-theme='light']`, без `prefers-color-scheme`. Это нормально для статического
макета без JS-логики, но **не переносим** как есть: в приложении уже работает более правильное
поведение — светлая/тёмная по `prefers-color-scheme`, ручной выбор через `ThemeToggle` поверх
(`lib/theme.ts`, `localStorage`). Меняем только палитру внутри существующих блоков `:root`,
`@media (prefers-color-scheme: dark) :root:not([data-theme='light'])` и `:root[data-theme='dark']`
(их три, держать в синхроне — уже так сегодня).

## 5. Порядок внедрения (этапы, каждый — отдельный PR/коммит)

1. **Токены** (§ 2) — `globals.css`. Готово = обе темы визуально не ломаются, только чуть контрастнее hover.
2. **Общие примитивы** (§ 4.1) — `ui.module.css`. Пока не подключены нигде, кроме, возможно, `.pill` сразу в `MatchCard` (первый реальный потребитель, чтобы не копить мёртвый CSS).
3. **Компоненты** (§ 4.2) — по одному, начиная с самых переиспользуемых: `AthletePhoto` → `AthleteCard`/шапка профиля → `MatchCard` → `ScoreReveal`/`StatsReveal` → `RatingBadge` → остальное.
4. **Страницы** (§ 4.3) — после того как их компоненты уже перекрашены, остаются только правки раскладки самой страницы.

На каждом этапе — `npm run lint` / `npx tsc --noEmit` / `npm run build` (AGENTS § 2) и ручная проверка
в браузере: обе темы, ширина 375px и 1280px, как требует `design/README.md`.
