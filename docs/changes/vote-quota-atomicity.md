# Атомарные квоты голосования — этап B

Статус: реализовано 2026-09-22 по явному заданию пользователя; основной договор и результаты —
[project-audit.md § B и § 5а](project-audit.md). Этот документ заменяет первоначальный черновик
с несколькими запросами в Payload-транзакции и изменением ipHash при повторе.

## Решение

- Квоты только новых строк: 5 устройств/матч/IP/24 часа и 60 голосов/IP/час.
- Повтор — `(match, deviceId)` независимо от даты и текущего IP. Обновляются четыре оценки и
  `updatedAt`; `id`, `createdAt`, исходный `ipHash`, `isHidden` сохраняются.
- Один параметризованный INSERT SELECT ON CONFLICT DO UPDATE RETURNING в `writeVote.ts`:
  существующая пара либо обе свободные квоты. Лимиты из `rateLimiting.ts`.
- Окна строго `createdAt > now - window`; скрытые голоса учитываются.
- Проверки ботов, матча и окна выполняются до записи, в том числе для повторов.
- Пустой RETURNING означает RATE_LIMITED. Ошибки БД проходят в контролируемый JSON 500;
  запасного update и прикладных повторов нет. Адаптер ждёт блокировку до 1000 мс.
- Схема, миграции и коллекции не меняются; действий пользовательских hooks Votes нет.
  SQL сохраняет default isHidden и ISO UTC даты; вход валидирует существующая схема Zod.

## Границы

**Turso не проверен.** SQLite не подтверждает Turso. Браузер недоступен (`No browser is available`,
список `[]`), поэтому клики, модалка и обновление UI остаются непроверенными.
Без Production, рабочей БД и деплоя. Удаление матчей — D, запуск миграций — C;
athleteStats и дизайн не входят в B. Уже существующие макеты дизайна сохранены отдельным коммитом.
