# design/ — статические макеты ArmReview

Папка с HTML-макетами интерфейса. Нужна, чтобы договориться о виде и поведении страниц
до того, как они появятся в приложении: что где лежит, что скрыто спойлером, как это
выглядит в обеих темах и на телефоне.

## Чем это НЕ является

- **Это не код приложения.** Отсюда ничего не импортируют — ни компонентов, ни стилей.
- **В сборку не попадает.** `next build` эту папку не видит, `ui.css` не подключается
  к приложению. Живое приложение стилизуется своими CSS Modules и токенами `globals.css`.
- **Это не рабочий прототип.** Данные — заглушки, формы ничего не отправляют, ссылки
  ведут между статическими файлами. Ни базы, ни API за ними нет.

Макет — это **источник требований к вёрстке**, а не исходник. Переносят из него решение
(структуру блоков, порядок, поведение), а не файлы.

## Как смотреть

Открыть `index.html` двойным кликом в браузере. Сервер не нужен — всё работает с `file://`.
`index.html` — оглавление, из него ссылки на все остальные макеты.

Проверять нужно **обе темы** (кнопка `◐` в правом верхнем углу) и **ширину 375px**
(DevTools → мобильный вид): вёрстка mobile-first, горизонтального скролла быть не должно.

## Из чего состоит

| Файл | Роль |
|---|---|
| `ui.css` | **Единственный источник стилей.** Токены обеих тем, каркас, все примитивы. |
| `_shell.html` | Образец каркаса: `<head>`, `.header`, `.footer`, общий `<script>`. Не страница — шаблон для копирования. |
| `index.html` | Оглавление: список макетов и правила. |
| остальные `*.html` | Страницы сайта и витрины дизайн-системы. |
| `contrast-report.md` | Отчёт по контрасту цветовой системы. |

### Правило: новый примитив идёт в `ui.css`

Если на странице понадобился элемент, которого нет в `ui.css`, — он добавляется
**в `ui.css`**, а не в `<style>` этой страницы. Иначе у каждой страницы заводится свой
вариант кнопки, карточки и шкалы, и через три макета стиль разъезжается так, что
переносить его в приложение уже бессмысленно.

Локальный `<style>` допустим только под раскладку, которая нужна ровно одной странице
и никому больше (например, сетка оглавления в `index.html`). Цвет в локальном `<style>`
не пишется никогда — только `var(--токен)`, и токен обязан быть определён в обеих темах.

## Что из этого требует новых полей в базе

Блоки с плашкой **«НЕТ ДАННЫХ В БАЗЕ»** (класс `.future`) нарисованы по данным, которых
в Payload сейчас нет. Их нельзя реализовать, пока схема не расширена:

- **Справочник стилей борьбы** — 10 фиксированных стилей вместо произвольной строки.
- **Тип борца** — инсайд / аутсайд / универсал как перечисление.
- **Позиция на шкале** инсайд↔аутсайд — числовое значение, а не просто категория.
- **Пораундовая статистика в разрезе стилей** — кто каким стилем какой раунд выиграл.
- **Время, проведённое в каждом стиле** — для составной полосы распределения.

**Главный блокер:** поле «стиль» у борца сейчас — **свободный текст**. Пока оно не станет
ссылкой на справочник, агрегировать по стилям нечего: «Top Roll», «топролл» и «top-roll»
для базы разные значения. Большая часть блоков выше упирается именно в это, а не в
отсутствие самих полей.

Порядок разблокировки: справочник стилей → тип борца и позиция на шкале → пораундовая
статистика → время в стилях.

## Решённые вопросы дизайна

### Красный цвет занят дважды

В системе два красных, и они означают разное:

- `--loss` — **поражение** в матче;
- `--inside` — **инсайд-пуллер**, тип борца.

Оттенки близкие, и без правила карточка борца-инсайдера читалась бы как «проиграл».
Решение — **разделить по форме, а не по оттенку**:

- **Исход матча** кодируется **сплошной заливкой**: `.wl--w` / `.wl--l`, `.split`,
  `.statline--win` / `.statline--loss`.
- **Тип борца** кодируется **только обводкой и текстом**: `.t-inside`, `.stylebadge`,
  `.avatar--inside`. Сплошной заливки у типа борца не бывает; максимум — еле заметная
  подсветка фона `--inside-tint` в шапке (`.hero--inside`).

То есть «залито = результат, обведено = тип». Это правило обязательно соблюдать и в
приложении: если тип борца где-то зальют сплошным цветом, семантика сломается сразу.

### Цвет никогда не единственный носитель смысла

В каждом случае цвет **дублируется подписью**: «ПОБЕДА» / «ПОРАЖЕНИЕ» рядом со счётом,
«ИНСАЙД» / «АУТСАЙД» / «УНИВЕРСАЛ» на бейдже типа, подписи на концах каждой шкалы.
Это требование доступности: макет должен читаться при дальтонизме и в чёрно-белой печати.
Замеры контраста для обеих тем — в `contrast-report.md`.
