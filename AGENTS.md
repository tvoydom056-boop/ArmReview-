# AGENTS.md — как пишется код в ArmReview

Что делаем и зачем — [../PROJECT.md](../PROJECT.md). Слои, дерево файлов и решения —
[../STRUCTURE.md](../STRUCTURE.md). При конфликте эти документы важнее этого файла.

## 0. Что читать — экономим токены

Этот файл загружается всегда, и для обычных правок его достаточно.

| Ситуация | Что читать |
|---|---|
| **Нетривиальное изменение**, для которого есть план | `docs/changes/<имя>.md`; в STRUCTURE/PROJECT — только §, на которые он ссылается |
| **Первый промт** новой задачи: новый срез, фича, страница, папка, слой | нужные § `../STRUCTURE.md` и `../PROJECT.md` — один раз за задачу |
| **Правки 2, 3, 4…** в той же задаче: баг, стиль, текст, проп, рефактор | только изменяемые файлы. STRUCTURE.md и PROJECT.md **не читать** |
| Сомнение в правиле продукта (спойлеры, антинакрутка, формула) | один нужный § PROJECT.md |

- Документы — не целиком: `Grep "^## "` по файлу → `Read` нужного § через `offset`/`limit`.
- `payload-types.ts`, `node_modules/next/dist/docs/` — только `Grep` по имени типа или API.
- Не читать: `package-lock.json`, `*.db`, `.next/`, `*.tsbuildinfo`, `../ArmReview_*.pdf.md` (устаревшие ТЗ).
- Уже прочитанный или только что отредактированный файл повторно не читать.
- Длинный вывод (`build`, `lint`) — только хвост: `| Select-Object -Last 30`.

## 1. Next.js 16 — не тот, что ты помнишь

Next 16.3 + React 19.2 + Payload 3.90. Незнакомый или «очевидный» API сверяй с
`node_modules/next/dist/docs/`, а не с памятью. Уже известно:
- `params` / `searchParams` — `Promise`, их нужно `await`-ить;
- `middleware.ts` → **`proxy.ts`** (экспорт `proxy`);
- `payload build` нет — сборка через `next build`.

## 2. Готово = всё зелёное

`npm run lint` · `npx tsc --noEmit` · `npm run build` — без ошибок.
Поменял `collections/` → `npm run generate:types`, а до деплоя — `npm run payload migrate:create`.
Результат проверен в браузере. Ошибки не глушим (`@ts-ignore`, `eslint-disable`) — чиним причину.

## 3. Слои и импорты

| Где | Можно | Нельзя |
|---|---|---|
| `components/` | `components/`, типы и чистые функции из `lib/` | `payload`, `@/lib/payload`, `collections/` |
| `app/**/page.tsx` | `components/`, `features/`, `lib/` | `collections/` |
| `app/api/**/route.ts` | `features/*/service.ts`, `schema.ts`, `lib/` | бизнес-логику в самом роуте |
| `features/<x>/` | `lib/`, `components/` | другие `features/` |
| `lib/` | `lib/`, типы | React, Next, `payload` (кроме `payload.ts`, `deviceId.ts`) |

- **Страница** загружает данные через `getPayloadClient()` и отдаёт компонентам простые пропсы.
- **Компонент** получает узкий тип, а не документ Payload (`AthleteCard` → `photo: { url, alt } | null`).
- **Правила и адаптеры** — чистые функции в `lib/` (`computeAthleteStats`, `getPhoto`).
- **`features/`** — только для сложных сценариев (сейчас одно голосование).

## 4. Переиспользование

1. Перед кодом ищи готовое в `components/`, `lib/`, `collections/access.ts`, `globals.css`.
2. Нужен вариант — добавь проп (`AthletePhoto size="profile"`), не копируй компонент.
3. В общее выносим при **втором** использовании. До этого код живёт рядом (`HandCell` в `StatsReveal`).
4. Повторяющийся запрос → `lib/queries/<сущность>.ts`; повторяющееся поле коллекции → фабрика (`scale()`).
5. Без «на будущее»: UI-китов, генерик-хуков, репозиториев поверх Payload.

## 5. React / Next / TS

- По умолчанию Server Component. `'use client'` — только на листе с состоянием (`StatsReveal`).
- В клиент передаём только нужные поля. Общий запрос страницы и `generateMetadata` — через `cache()`.
- Нет данных → `notFound()`. В `payload.find` явно задаём `depth`, `limit`, `pagination`.
- Хуки коллекций — только `revalidatePath`. React Query — только для клиентских мутаций.
- `strict`, без `any` и `as`-заглушек. Типы сущностей — из `payload-types.ts` (не правим руками).
- Именованные экспорты; `default` — только где требует Next. Импорты через `@/`.

## 6. Стили

CSS Modules рядом с компонентом. Цвета и радиусы — только токены из `globals.css`;
новый цвет — токен в обе темы. Mobile-first.

## 7. Инварианты продукта

- Счёт, победитель, статистика — только за кнопкой; в OG и `<title>` результата нет.
- Сырой IP не храним и не логируем — только `ipHash`; IP берём из заголовка нашего Caddy.
- Каждая коллекция — с явным `access`. Payload создаёт REST-маршруты, но доступ по умолчанию
  требует `req.user` (проверено для 3.90.0); публичное чтение задаём явно. `votes` закрыта.
- Голос — upsert через уникальный индекс `(match, deviceId)`; бот-проверки отвечают `200 OK`.
- `.env` и `armreview.db` не коммитим.

## 8. Процесс

- Нетривиальное изменение (фича, правило голосования, схема данных) — сначала план
  `docs/changes/<имя>.md` по образцу `slice-2-voting.md`: сценарии WHEN/THEN, задачи, открытые
  вопросы. Код — после «ок» Danil. Итог: в файле у каждого сценария указано, чем он проверен.
  Мелкая правка (стиль, текст, баг в одном файле) — без плана.
- Минимальный дифф; попутный рефакторинг — отдельно. Сменилась структура → обновить STRUCTURE.md.
- Комментарии на русском, про «почему», со ссылкой на § документа.
  Открытый вопрос к Владу → дефолт + `TODO(вопрос N)`.
- Тесты — Vitest рядом с файлом, только чистые функции (формула, хеш, лимиты, валидация).
- Не делаем: аккаунты и пароли, лишние зависимости, GraphQL/Redis/очереди, правки `src/app/(payload)/`.
