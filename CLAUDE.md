# Дополнительно для Claude

Общие правила — в AGENTS.md (подключён выше). Здесь только то, что касается Claude.

- **Режим — прикладной.** В проекте выбран режим «код пишет Claude, Danil ревьюит»
  (PROJECT.md § 4). Сократовский режим здесь не нужен, если Danil сам не попросит разобрать тему.
- **Код пишется под ревью.** Минимальный дифф, в отчёте: что изменено, почему так,
  какие проверки из AGENTS.md § 2 прошли (с выводом), что открыть в браузере.
- **Токены — по AGENTS.md § 0.** STRUCTURE.md и PROJECT.md — только на первом промте новой
  задачи, на последующих правках — нет. Широкий поиск по коду — через субагента (context-explorer).
- **Одна задача — одна сессия.** Новый срез или несвязанная задача → совет Danil'у сделать `/clear`;
  длинная сессия → `/compact`. Тяжёлые файлы закрыты от чтения в `.claude/settings.json`.
- **Next 16 / Payload 3.90** — сверяй API с `node_modules/next/dist/docs/` и типами пакетов,
  а не с памятью (AGENTS.md § 1).
- **Среда — Windows, PowerShell 5.1:** нет `&&`, нет `head`/`tail`; для POSIX — Bash-инструмент.
- **Сам не делаешь:** не создаёшь админа и пароли, не коммитишь без просьбы,
  не трогаешь `armreview.db` на сервере, не деплоишь.
- Это единственные AGENTS.md и CLAUDE.md проекта: если генератор (create-next-app,
  create-payload-app) создаст свои — не затирай эти, перенеси полезное вручную.
- **План → «ок» → код.** Для нетривиального изменения сначала напиши `docs/changes/<имя>.md`
  по образцу `slice-2-voting.md` и остановись: код до ответа Danil не пиши.
- **Открытые вопросы плана — Danil'у.** Дай предложение по умолчанию, но решением его делает
  только ответ Danil. Расхождения между документами выноси в план, а не правь молча
  STRUCTURE.md / PROJECT.md.
- **После кода** — сверь план с фактом: отметь, чем проверен каждый сценарий (тест или
  ручная проверка), в отчёте покажи эту таблицу. Не заявляй «проверено» без запуска.
